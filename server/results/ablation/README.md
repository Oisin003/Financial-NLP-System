# Ablation Study Results

This folder stores output files generated by:

```bash
npm run ablation
```

## What This Study Is For

An ablation study helps you answer:

- Which audit rules are doing useful work?
- What happens to detection quality if one rule is removed?

It does this by comparing:

- `baseline` (all rules enabled)
- `no_*` variants (one rule or rule group disabled)

## How To Run

From the project root (`e:\Financial-NLP-System`):

```bash
npm run ablation
```

The root script delegates to the server script automatically, so you do not need to manually change directories.

## Files You Will See

Each run creates timestamped files and refreshes `latest.*`.

- `ablation-<timestamp>.json`: Full detailed results (per-variant + per-case)
- `ablation-<timestamp>.csv`: Table-friendly summary
- `latest.json`: Most recent run details
- `latest.csv`: Most recent run summary table

## How To Read The Table

Columns in the CSV/terminal summary:

- `variant`: Which configuration was tested
- `precision` (`P`): Of the flags predicted, how many were correct
- `recall` (`R`): Of expected flags, how many were found
- `f1`: Balance between precision and recall
- `rag_accuracy`: Accuracy of RAG status prediction (`red/amber/green`) only
- `tp`, `fp`, `fn`: True positives, false positives, false negatives
- `duration_ms`: Runtime in milliseconds

## Quick Interpretation Guide

Use `baseline` as your reference row.

- If a `no_*` variant has lower `recall` or `f1`, the removed rule is likely valuable.
- If scores stay similar after removing a rule, that rule may be redundant on this dataset.
- If precision drops, the variant may be generating noisier flags.

## Notes

- These results are only as good as the labeled dataset in `server/scripts/runAblationStudy.js`.
- Keep the dataset stable when comparing model/rule changes over time.
- Add new labeled cases if you want stronger confidence before changing production rules.
